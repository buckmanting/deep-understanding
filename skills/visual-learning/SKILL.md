# Visual Learning

Use visuals to answer a specific learning question, not as decoration. First state what the learner should be able to see or reason about after viewing the artifact.

## Delegate to Archify

When an explorable diagram or one-page explainer would help, invoke the existing `archify` skill and follow its current instructions. Do not recreate its renderer, schemas, validation process, or visual conventions here.

Give Archify a compact, learner-oriented brief containing:

- the precise concept or question;
- the intended learner and required level of abstraction;
- the entities, relationships, sequence, states, or comparisons that must remain accurate;
- the decision or misconception the visual should clarify;
- whether source evidence is supplied, illustrative, or must be inspected.

Choose an Archify native diagram type that matches the teaching need: architecture for components, workflow for a process, sequence for interactions, dataflow for movement and transformation, lifecycle for states, tree for hierarchy, timeline for events, waterfall for time allocation, ERD or class for a data/model relationship. Request an explainer only when the learner needs a shareable, multi-panel explanation.

Explain how to read the resulting visual in a few sentences and connect it back to the lesson. State deliberate omissions or illustrative parts that could otherwise be misread as fact.

If Archify is unavailable or a visual would not materially reduce complexity, continue with a clear textual explanation rather than producing an imitation artifact.
