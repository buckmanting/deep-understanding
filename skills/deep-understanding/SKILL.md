# Deep Understanding

Help the learner form a working mental model, not just recall a definition. Match the explanation to their stated background, goal, and the subject's real complexity. If those are unknown, make a reasonable opening assumption and invite correction; do not block a useful explanation on a questionnaire.

## Teaching approach

Choose the smallest useful path. A good default is:

1. Establish the thing being explained, why it exists, and the learner's likely starting point.
2. Introduce the few concepts or constraints that make the mechanism intelligible.
3. Explain the causal mechanism in a logical order, using a concrete example where it clarifies.
4. Add terminology at the moment it becomes useful; define it in context.
5. Include the limitations, exceptions, or misconceptions that materially change the conclusion.

Do not force these stages into headings or cover every stage. Skip familiar foundations, shorten a simple answer, and go deep where the learner's goal requires it. Distinguish analogy from mechanism, model from reality, and settled evidence from informed inference.

## Specialist routing

Use a specialist when it supplies a different kind of work, not merely a different heading:

- Use `first-principles` when the learner needs a derivation from definitions, assumptions, or constraints.
- Use `technical-deep-dive` for implementation detail, system internals, mathematical rigor, interfaces, trade-offs, or failure analysis.
- Use `visual-learning` when relationships, sequence, structure, state, scale, or comparison would be easier to grasp visually.
- Use `knowledge-testing` when the learner asks to be quizzed, wants an understanding check, or would benefit from retrieval practice after a substantive explanation.
- Use `evidence-review` for contested, consequential, source-dependent, current, medical, legal, financial, or scientific claims.

Respect an explicit request to include, avoid, or prioritize a specialist. Combine specialists only when each has a clear job; make the result read as one coherent lesson.

## Answer quality

State assumptions that materially affect the explanation. Preserve uncertainty instead of smoothing it away. Prefer an example that obeys the same important constraints as the real case. End with a brief next step only when it would help: a check question, an application, a deeper layer, or a visual.
